## 环境与操作约定

使用独立 worktree、专用超平坦创造世界、允许命令、默认配置。准备相同的原版测试数据包
`fixtures/`，通过游戏聊天执行 `/reload`，再执行 `/function ectgui<名称>` 准备场景
（例如 `/function ectguicbase`）。这些纯字母别名转发到 `ectgui:` 命名空间，
避开特殊字符输入和异步 Tab 补全的不稳定性。函数会清空测试玩家背包并重置
`0 -60 2` 的台子，只能在专用测试世界使用。函数只准备材料，不调用模组内部菜单方法。

表格里的 H0、H1…指快捷栏第 1、2…格。完成关键操作后截图，并在关闭菜单后执行
`/function ectguiinspect` 读取服务端方块和玩家物品组件。存档检查中不能重新运行准备函数。
GUI 画面与服务端数据不一致时判失败并保留两份证据。普通关闭重开、存档重载分别测试。
搜索、重载、切换场景后先确认候选或窗口已经刷新，再进行依赖该状态的点击。
快速连续输入与点击另作竞态用例，不混入稳定状态的判定。

| ID | 准备和实际操作 | 预期结果 |
| --- | --- | --- |
| C01 | `cbase`，右键转换台，观察空界面 | 书本/支付/模板/复制输出与候选槽不重叠，空候选 `-/-`，无多余默认标题 |

| C03 | `cboundary`，先放 H1 的 35 绿宝石；再放 H0 的 2 本书；最后补 H2 的 1 绿宝石 | 无书、35 绿宝石都无结果；达到 36 才出现候选 |
| C04 | 接 C03，搜索 sharpness，领取到空快捷栏 | 得到 Sharpness V；剩余 1 本书、0 绿宝石，候选清空 |

| C06 | `cbase`，放材料；翻到第 2 页；搜索 sharpness、无匹配词，再清空 | 页码和候选随操作更新；清空恢复；无匹配显示 `-/-` |
| C07 | `ccopy`，先只放书和付款，搜索 sharpness；连续普通领取两次 | 每次都正确扣费；材料尚够时被取槽及时补位，筛选不丢失 |
| C08 | `ccopy`，放书、付款、H2 合法模板；领取复制结果到背包 | 候选区禁用；输出 Sharpness V；每次生成扣 1 书/4 块；模板保留 |
| C09 | `ccopy`，依次尝试 H3 多附魔、H4 超上限、H5 工具作为模板 | 均拒绝，原物不变；合法模板移走后恢复普通兑换模式 |
| C10 | C04/C08 操作后关闭菜单再打开 | 材料、模板、复制结果与玩家所得保持，无幽灵书 |
| C11 | C04/C08 操作后保存退到标题并重进，重新读取服务端数据 | 消耗不能回滚，结果不能复制，所有持久槽保持 |
| C12 | `cbase` 放材料，关闭菜单执行 `reloadlater` 后立刻重开；待 reload 后搜索或翻页，并领取 | 菜单继续有效，候选来自当前注册表，无过期槽位 |
| E01 | `esync` 放 H0 四附魔剑；依次普通领取前两本再领取后两本 | 正确移除指定附魔；前两槽留空，后两本仍可取，无幽灵/错位 |
| E02 | `esync`，以 Shift 左键连续取前两本，再普通取后两本 | 同 E01，且前两本直接入背包；重点观察历史 `C,D,空,D` 错位 |
| E03 | `einsert` 放剑；将 H1、H3 书依次用点击拿起、点击输入槽放入 | 剑增加对应附魔；输入书被消耗，输入槽清空 |
| E04 | `einsert` 放剑，将 H2 书放右侧空候选槽 | 增加 Unbreaking I，光标书消耗，原剑其他附魔保留 |
| E05 | 已有 Unbreaking I 时，把 H4 同级书放到同名候选槽 | 变为 Unbreaking II，只消耗一次，光标无残留可再次使用的书 |
| E06 | `einsert` 放剑；Shift 左键输入附魔书 | 成功应用且原书消耗，无输入槽残留 |
| E07 | `esplit` 放 Looting III；取 Looting I 再放回候选区，连续 3 次 | 每轮 III→II→III，不能重复增级；光标清空，重开状态一致 |
| E08 | `esync` 放剑并点击导出 | 一册含全部 4 个附魔的书进入背包/光标；剑清空附魔，候选清空 |
| E09 | `einsert` 放剑，尝试普通书/泥土进入附魔输入槽 | 拒绝；剑和输入物品保持原状 |
| E10 | E03/E04/E05/E08 后关闭重开，再保存重载 | 主物品组件及玩家所得保持，不回滚、不复制 |

## 配置用例

在退出客户端后备份专用 run 目录的配置，开启 `incrementalSameLevelMerge`、
`enforceEnchantmentLevelLimit`、`convertOnlyLevelOneBook` 和 `freeConversionTableCosts`。
其他数值保持默认。两个加载器使用相同配置；测试结束恢复原文件。

| ID | 准备和操作 | 预期结果 |
| --- | --- | --- |
| K01 | `estrict`，剑 Sharpness II + 同级书 | 得到 III，书消耗 |
| K02 | `estrict`，剑 II + I；再尝试包含 Sharpness I/Unbreaking I 的混合书 | 两次均原子拒绝；剑仍 II，Unbreaking 不应部分加入，书不消耗 |
| K03 | K01 后加入 III 得 IV，再用同级 IV→V；最后 V+V | 可到 V；超上限尝试拒绝，物品不变 |
| K04 | `estrict`，给没有 Looting 的剑加入 Looting IV | 允许新增超过原版上限的条目，书消耗 |
| K05 | `efree`，空转换台搜索 sharpness 并领取 | 免费候选为 Sharpness I，不需要书/付款 |
| K06 | 接 K05，尝试放普通书与付款；再放合法 Sharpness V 模板领取复制 | 输入槽拒绝材料；复制输出仍为模板的 V，模板保留且可持续取出 |
