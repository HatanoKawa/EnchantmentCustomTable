# 1.21.1 原生 Shift GUI 补测（2026-09-26）

结论：独立 macOS 原生输入辅助程序可在 1.21.1 的 Fabric 和 NeoForge 客户端执行真实
Shift 左键。此前 E02/E06 共 4 项历史阻塞均补测通过；两端严格配置的 Shift 拒绝与合并扩展
也通过。本轮未发现新的模组缺陷，未修改生产代码。26.3 的输入问题记录为
**INPUT-26.3-01**，按用户要求留待讨论，本轮没有启动或重新验证 26.3。

## 基准与方法

- 分支 `dev`，业务代码基准 `a347ed0`（已有 26.3 适配）。
- Minecraft 1.21.1；Fabric Loader 0.19.3 / Fabric API 0.116.12+1.21.1；NeoForge 21.1.136。
- Gradle 使用本机 Java 25；两个客户端使用导出的 `runClient` Java 21 toolchain。
  重新执行双端 `exportGuiClientLaunch` 成功，实际客户端通过现有 `.app` 启动器运行。
- 使用独立 `ECT-SHIFT-fabric-1.21.1`、`ECT-SHIFT-neoforge-1.21.1` 世界，
  从同版本第二轮世界复制。数据包仅准备材料和读取原版服务端物品数据，不调用模组业务方法。
- GUI Scale 2、窗口模式；默认配置与严格配置分别启动客户端。
  严格组仅开启 `incrementalSameLevelMerge` 和 `enforceEnchantmentLevelLimit`，
  两个免费/一级转换开关仍关闭。
- 普通操作、菜单观察和 F2 截图使用 Computer Use；用户授权的
  [原生辅助程序](macos_shift_click.swift)通过 CGEvent 发送 Shift 与鼠标事件。
  业务判断结合实际画面、物品数量和 `ectguiinspect` 读出的服务端组件。

原工具无法表达“持续按住 Shift 时点击”的接口限制仍存在。辅助程序补充这项输入能力，
不替换模组菜单处理，也没有用直接调用 `quickMove` 或修改物品数据冒充 GUI 操作。
程序回执本身不作为通过证据。使用与坐标校准见 [README](README.md#1211-原生-shift-点击)。

## 实际执行

| 用例 | 操作与观察 | Fabric | NeoForge |
| --- | --- | --- | --- |
| 输入对照 | 原版箱子：16 泥土从快捷栏 Shift 移入箱子，再 Shift 移回；随后普通点击将物品拿到光标，确认修饰键释放 | PASS | PASS |
| E02 | `esync` 四附魔剑；Shift 连续取前两本，普通点击取后两本。前两格正确留空，剩余两本可取；最终四本各 1，剑无附魔，无幽灵/错位/重复；关闭重开、保存重进一致 | PASS | PASS |
| E06 默认 | `einsert` Sharpness I 剑；Shift 依次输入 Sharpness I、Unbreaking I、Looting I、Unbreaking I。四书各消耗一次，输入槽清空；剑最终 Sharpness II / Unbreaking II / Looting I | PASS | PASS |
| E06 无效物品扩展 | Shift 普通书与泥土，均不进入台内、不改变剑，数量保持；它们通过正常快捷移动回退到主背包。退出客户端并重新进入后所有组件/数量保持 | PASS | PASS |
| E06 严格配置扩展 | II 剑先 Shift 输入 I 及 Sharpness I / Unbreaking I 混合书，均完整拒绝；随后同级 II→III→IV→V，新增 Looting IV 成功，各消费一次；最后 V+V 被拒绝。保存重进一致 | PASS | PASS |

计数口径：**4 项既有用例转为 PASS**；输入对照和 E06 扩展是补充步骤，不把它们叠加到
原 28/30 项矩阵中。E02 按既有定义执行“前两本 Shift、后两本普通”，没有声称覆盖四本
全用 Shift 或高频无等待连击。

两端生成书顺序不同，但最终附魔集合完全一致：Sharpness III、Looting III、Unbreaking III、
Mending I 各一本。Fabric 本轮 Shift 取出 Looting/Mending，NeoForge 取出 Unbreaking/Mending；
不能用固定附魔顺序跨端判断错位。

严格组最终剑为 Sharpness V / Looting IV，玩家保留三本被拒绝的书：Sharpness I、
Sharpness I / Unbreaking I、Sharpness V，各 1。它们从快捷栏移到主背包，组件完整，
Unbreaking 未部分加入剑。此行为符合快捷移动回退，不是拒绝失败或丢失物品。

## 交付与边界

两端客户端均正常退出，临时 `caffeinate` 已结束。两个配置文件和两个 `options.txt`
均恢复为测试前内容并逐字节比对。专用测试世界保留，便于后续复现。
本轮只增加测试输入辅助程序、原版箱子对照 fixture 和验证文档/证据，不需要业务修复。
验证包括 Swift 编译、双端启动参数导出和上述实际 GUI 执行；未把之前的 JVM 矩阵算作本轮新执行。

1.21.1 这四项 Shift 用例已不需要用户手动补测；其他全量版本、legacy 的 Shift 阻塞保持原状态，
仍需分别运行。INPUT-26.3-01 的 SDL 坐标问题与跨版本资源读取 MIG-01/MIG-02 继续保留原记录。
满背包、多人、拖拽分配、快捷数字键、全配置组合、高频输入压力等专项仍未覆盖。
当前辅助程序仅允许两种 1.21.1 专用应用身份；不宣称跨版本或长时间无人值守可靠。
